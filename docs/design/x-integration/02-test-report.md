## 发现的问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 增量同步时水位以下旧帖仍随首页返回 | 仅被判重拦下，无错误入池，但每轮重复评估 | 采集端过滤 `id <= stop_id`，补测试；真实复测返回 0 条 |
| 预览遇限流不写冷却（代码审查发现） | 预览后立即同步或调度会再次撞限流 | 预览与同步共用冷却写入，`json_set` 只改标记；补测试 |
| 扫到一半被限流（partial）不写冷却（代码审查发现） | 调度器看到待续扫会立刻再跑一次，本地判出会话被锁后才写冷却 | 结果带重试时间就写冷却，不再限定失败状态；补测试 |
| 新置顶的帖子每轮重复返回（代码审查发现） | 只被判重拦下，但每轮重复评估 | 置顶帖计入水位、不触发到达判断；补测试 |

## 复现

```bash
cd workers/python
uv sync --extra x
uv run python -m openlore_collectors.x_user.accounts add <标签>   # 提示后粘贴 Cookie
uv run pytest -q
```

服务端在来源页添加“X 账号”来源后预览、同步；离线测试：`apps/server` 下 `vitest run test/x-source.test.ts`。
