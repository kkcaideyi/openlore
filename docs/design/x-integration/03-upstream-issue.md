**标题：** 提议：新增 X 账号来源（twscrape 直连，可选依赖）

**正文：**

想给来源增加一种类型：X 账号。填写账号主页后，定时采集该账号的原创帖、引用帖和自串回复，进入现有的准入、初审、研读和归档链路。已在 Fork 上实现并用 3 个账号跑通取数，想先确认方向是否可以接受，再整理 PR。

**实现方式**

- Python 侧用 [twscrape](https://github.com/vladkens/twscrape) 0.20.1（MIT）作为 `workers/python` 的可选依赖 `x`，不装不影响 RSS。
- 新增 `x_user` 来源类型和 `collect_x_user` 子进程操作，Node 对返回做 Schema 校验。复用现有来源选项和内容池，不改调度、执行器和归档。
- 需要使用者自备一个已登录的 X 会话 Cookie，用命令行导入到控制端数据目录；不进入 Git、日志和 AI 执行机。
- 帖子 ID 作为唯一身份，x.com/twitter.com 链接归一；发帖时间与 ID 内嵌时间交叉核验，不回抓 X 网页；去链接后不足 40 字的帖子留待复核。
- 限流时来源进入冷却，期间不再请求 X。

**取舍**

- 用登录会话访问 X 的非公开接口，有违反 X 服务条款和账号受限的风险，接口变化时会失效。所以做成默认不启用、需显式安装和导入会话，风险由部署者承担。
- 对比过 RSSHub 路线：同样需要 X 会话，但要多维护一个常驻服务，RSS 再解析会丢掉引用、长帖等结构信息。
- 不合并线程、不同步编辑删除、不转写图片视频。

**改动范围（约 1300 行，含 ~500 行测试）**

contracts 新增 `x-source.ts`；server 新增 `collectors/x_user/`，`collection/{service,quality}.ts`、`scheduler.ts`、`sources/service.ts` 各少量改动；Python 新增 `x_user/`；来源页加一个类型。另外有一组独立于 X 的 `python/runner.ts` 修复（Windows venv 路径、子进程最小环境变量、错误输出脱敏），可以单独提。

**验证**

Python 18 项、server 新增 12 项离线测试通过，现有测试无新增失败。真实取数：3 个账号首扫 133 条，发帖时间全部与 ID 一致，入池 78 条，重复同步 0 新增。48 小时连续运行和端到端研读归档还在跑。
