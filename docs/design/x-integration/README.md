## 目标与范围

新增 X 账号来源：采集指定账号的帖子，进入现有内容池、初审、研读、归档与汇报链路。

首版包含：原创帖、引用帖（保留被引作者）、自串回复；帖子 ID、作者、发帖时间、正文（含长帖）、外链、媒体链接。

首版不含：线程合并、外链自动入池、图片/视频转写、全网搜索、编辑/删除同步、已归档帖自动重研、多账号轮换规避限流。

## 选型

**twscrape 直连，新增 `x_user` 来源类型。** RSSHub 路线未实现。

| 路线 | 结论 |
| --- | --- |
| twscrape → Python 采集 → `x_user` 适配器 | 采用。结构化字段直接可用；会话、分页、限流状态已有封装；无需常驻中间服务 |
| RSSHub → 现有 RSS 链路 | 未采用。需另部署服务，RSS 再解析会丢类型信息，本机部署还需放开私网访问；会话要求与直连相同 |
| Twikit | 备选。限流与分页需自行封装，`text` 字段可能截断长帖 |
| Nitter / 官方 API | 不考虑。实例 RSS 不稳定；官方 API 需付费权限 |

twscrape 固定为 `0.20.1`（MIT），作为 `workers/python` 的可选依赖 `x`。使用时需注意：

- MIT 只覆盖库代码，不代表数据接口授权；须使用团队有权使用的 X 会话。
- 默认会无限等待可用账号，已改为 `raise_when_no_account=True` 加任务级截止时间。
- 后续页失败时已产出的结果需保存，不能吞掉异常记为完成。
- 被拦截时可能表现为空页；解析失败会把原始响应写入 `/tmp/twscrape`。
- `tweet_thread()` 不是完整线程重建器。
